## 1. Опис проєкту

**CyberClub Desktop** - це кросплатформний десктопний застосунок для операційних систем Windows, macOS та Linux, створений за допомогою фреймворку **Electron 45.2.2** та компонентної архітектури **Feature-Sliced Design (FSD)**.

Застосунок забезпечує:
1. Оформлення нових бронювань відвідувачів із вибором ігрової зони (Standard Zone, VIP Lounge, Boot Camp 5x5, PlayStation 5 Arena) та автоматичною калькуляцією тарифу.
2. Клієнтську валідацію обов'язкових полів форми (блокування порожнього введення з візуальним сповіщенням червоного кольору).
3. Персистентне збереження даних у локальний JSON-файл `bookings.json` у системній директорії `%APPDATA%\cyberclub-desktop` засобами Node.js `fs` через міжпроцесну взаємодію (IPC).
4. Завантаження збережених бронювань під час запуску та підтримку повного відновлення стану.
5. Інтерактивне перемикання статусу («Активне» / «Виконано») та видалення записів.
6. Динамічний пошук і фільтрацію сесій «на льоту» за нікнеймом, зоною або статусом.
7. Суворе дотримання політики безпеки Electron: `contextIsolation: true`, `nodeIntegration: false`, використання безпечного моста `preload.js` через `contextBridge.exposeInMainWorld('cyberClubAPI', ...)`.

## 2. Архітектура Feature-Sliced Design (FSD)

Вихідний код інтерфейсної частини організовано за суворою методологією **Feature-Sliced Design**:

```text
lab-6/
├── package.json                 # Декларація залежностей та скриптів запуску (start: electron .)
├── main.js                      # Головний процес Electron (життєвий цикл, вікно, IPC, робота з fs)
├── preload.js                   # Preload-скрипт (contextBridge: cyberClubAPI)
├── README.md                    # Документація проєкту
└── renderer/                    # Рендер-процес (вебсторінка у вікні Chromium)
    ├── index.html               # Головна розмітка з мета-тегом Content-Security-Policy
    ├── style.css                # Геймерський темний дизайн з неоновими акцентами
    ├── script.js                # Точка входу рендер-процесу
    └── src/                     # Шари Feature-Sliced Design
        ├── app/                 # Ініціалізація та координація стану (index.js)
        ├── widgets/             # Самоврядні композитні блоки:
        │   ├── header/          # Віджет шапки з живою статистикою та касою (ui.js)
        │   ├── booking-form/    # Віджет форми з калькулятором тарифу (ui.js)
        │   └── booking-list/    # Віджет списку карток, пошуку та порожнього стану (ui.js)
        ├── features/            # Бізнес-сценарії користувача:
        │   ├── add-booking/     # Валідація, створення сутності та збереження через IPC (model.js)
        │   ├── delete-booking/  # Видалення/перемикання статусу та оновлення файлу (model.js)
        │   └── filter-bookings/ # Миттєвий пошук і фільтрація за вкладками (model.js)
        ├── entities/            # Предметна сутність бронювання:
        │   └── booking/         # Фабрика моделі, нормалізація даних та DOM-генератор картки (model.js, ui.js)
        └── shared/              # Перевикористовуваний фундамент:
            ├── api/             # IPC-клієнт із підтримкою fallback (ipcBridge.js)
            ├── config/          # Тарифна сітка зон клубу (zones.js)
            └── ui/              # Сервіс статусних повідомлень (notification.js)
```

## 3. Схема міжпроцесної взаємодії (IPC)

```text
┌────────────────────────────────────────────────────────┐
│               RENDERER PROCESS (Chromium)              │
│  - DOM, події, форми, UI-віджети FSD                   │
│  - typeof require === 'undefined' (безпечно)           │
│                                                        │
│  window.cyberClubAPI.loadBookings()                    │
│  window.cyberClubAPI.saveBookings(bookings)            │
└───────────────────────────┬────────────────────────────┘
                            │ contextBridge
                            ▼
┌────────────────────────────────────────────────────────┐
│                   PRELOAD SCRIPT                       │
│  - Ізольований міст contextBridge.exposeInMainWorld   │
│  - Виклики ipcRenderer.invoke('bookings:load' / 'save')│
└───────────────────────────┬────────────────────────────┘
                            │ IPC Channel
                            ▼
┌────────────────────────────────────────────────────────┐
│                 MAIN PROCESS (Node.js)                 │
│  - BrowserWindow(webPreferences: contextIsolation)    │
│  - ipcMain.handle('bookings:load' / 'bookings:save')  │
│  - fs.readFileSync / fs.writeFileSync                │
│  - Шлях: %APPDATA%\cyberclub-desktop\bookings.json    │
└────────────────────────────────────────────────────────┘
```

## 4. Інструкція із запуску

### 4.1. Встановлення залежностей
Перейдіть у теку `lab-6` та встановіть Electron:
```bash
cd lab-6
npm install
```

### 4.2. Запуск десктопного застосунку
```bash
npm start
```
Відкриється окреме вікно **CyberClub Desktop**.

## 5. Чек-лист покрокової перевірки працездатності

1. **Крок 1. Загальний вигляд:**
   У вікні відображаються: заголовок «CyberClub Desktop», лічильники статистики, форма бронювання ігрового місця та список бронювань.
2. **Крок 2. Перевірка порожнього поля:**
   Натисніть кнопку «Додати бронювання» з порожнім полем нікнейму (або пробілами). З'являється червоне повідомлення: `Будь ласка, введіть нікнейм гравця.` Запис до списку не додається.
3. **Крок 3. Додавання запису:**
   Введіть нікнейм гравця (наприклад, `s1mple`), оберіть зону та натисніть «Додати бронювання» (або клавішу `Enter`). Запис з'являється у списку, поле очищується, під формою виводиться зелене повідомлення: `Бронювання успішно додано та збережено у файл.`
4. **Крок 4. Видалення запису:**
   Натисніть «Видалити» біля запису. Запис зникає, виводиться повідомлення: `Бронювання видалено.`
5. **Крок 5. Збереження даних між запусками:**
   Додайте 2-3 записи, закрийте вікно застосунку. Запустіть знову командою `npm start`. Записи автоматично зчитуються з файлу `bookings.json`.
6. **Крок 6. Перевірка файлу bookings.json на диску:**
   У командному рядку Windows виконайте:
   ```cmd
   dir "%APPDATA%\cyberclub-desktop"
   type "%APPDATA%\cyberclub-desktop\bookings.json"
   ```
   Файл містить валідний JSON-масив об'єктів. При видаленні файлу застосунок відкривається з порожнім списком без помилок.
7. **Крок 7. Перевірка безпеки (DevTools: Ctrl+Shift+I):**
   - `typeof require` повертає `'undefined'`.
   - `window.cyberClubAPI` містить функції `loadBookings` та `saveBookings`.
   - `await window.cyberClubAPI.loadBookings()` повертає актуальний масив бронювань із файлу.
8. **Крок 8. Перезавантаження коду:**
   Зміна тексту в `renderer/index.html` застосовується комбінацією `Ctrl+R` без перезапуску застосунку.
